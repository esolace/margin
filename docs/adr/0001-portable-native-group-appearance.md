# Store GH1 appearance on the native group

GH1 appearance now travels in the native group's serialised object values, rather than depending solely on the definition's lookup by instance identity. Native copying changes identity; object-owned values survive that operation, save/reopen and native undo without replacing GH_Group or guessing which source group a copy came from.

The documented string GetValue/SetValue methods are protected. A small GH1 adapter binds them once as typed delegates, keeping this host-specific dependency out of the shared model and GH2 adapter. Native Rhino 9 copy and round-trip checks verify the integration; unsupported accessor signatures fail explicitly. A custom group subclass was rejected because it would replace the native object type and complicate files opened without Margin.

When attaching an older definition, promote legacy appearance onto each group before its first copy. Object-owned values take precedence. Writes also update the old definition entry for older Margin versions; this is read compatibility, not bidirectional synchronisation with edits made after downgrading. Revisit this adapter if Grasshopper exposes a public object-metadata API.

Ordinary groups without Margin metadata adopt explicitly saved local defaults on the first attachment of an opened definition. Without an explicit saved choice (`UseGroupColour`), they receive a snapshot of their current appearance. Both outcomes are portable before the first copy. Existing nonempty portable or legacy appearance is always protected, including corrupt/unknown values and historical automatic snapshots whose intent cannot be recovered.

The shared `GroupAppearanceSession` owns this adoption rule, preference readiness and document encounter history. `Start` loads preferences before calling the native attachment adapter, releases partial subscriptions on startup failure, and resets invalid preferences to safe unsaved defaults without rewriting the settings file. `Attach` identifies the first attachment in that start cycle; initialized group identities remain remembered for the lifetime of the document, including removal/undo and stop/start. Groups added while stopped are initialized when their definition reattaches. Getters perform no loading or attachment.

Later arrivals retain their native colour unless the host identifies a new group eligible for the existing defaults policy. GH1 uses empty/standard native colour; GH2 uses the explicit native Create/Group undo notification. Incoming metadata-free GH1 groups from an unencountered source cannot be distinguished from new groups when their colour is standard. Open the source with Margin before copying when its original appearance must be retained. A scan may precede GH2's creation notification: only the session's exact, fresh, unedited snapshot of that same identity can then be upgraded. This is transient session state, not new serialized provenance; copied, edited, older and legacy metadata remain protected.

Native adapters retain host subscriptions, native colour conversion, object metadata access, layout and undo. They request native appearance lazily, so idle scans of portable groups neither parse/serialize style nor rewrite metadata. `GroupStyle` and `Groups` editing contracts remain unchanged. Portable session tests exercise the rules and lifecycle; native open/copy/undo/save-reopen checks remain necessary for SDK event ordering and serialization.
